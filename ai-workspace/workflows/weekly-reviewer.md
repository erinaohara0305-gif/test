# 振り返り社員（weekly-reviewer）: ストーリーズ訴求の振り返りと施策案

- 使う場面: 毎週の定期実行（希望時刻: 毎日20:01 日本時間 とのことだが、内容が「週次の振り返り」のため、実際には直近7日間をまとめて出す。利用者の希望に合わせて実行頻度は調整可能）
- 目的: 自社講座（初心者向けの女性向け中古戸建て投資講座）の**集客**のため、Instagramストーリーズの訴求内容を振り返り、閲覧率を上げる施策案を作る
- 必要な入力: `inbox/weekly-reviewer/` に置かれた、その週のストーリーズのインサイト数値（テキスト・CSV・PDF・docxなど）。画像のみの場合は、利用者に数値のテキスト化を依頼する（この社員は画像を直接読み取れない）
- 参照するファイル: `AGENTS.md`、`context/business-profile.md`、`context/audience.md`、`context/offers.md`、`context/brand-voice.md`、過去の `output/weekly-reviewer/` の納品物（前回の施策案との重複・効果検証のため直近4回分を確認）
- 完成物: `ストーリーズ振り返り_期間開始_期間終了.md`（Markdown 1ファイル）
- 保存先: `claim` が返す `delivery_path`（`output/weekly-reviewer/<job_id>/attempt-N/`）
- 完成条件:
  - 対象期間（開始日・終了日）と、読み取った投稿件数
  - 投稿ごとの実績（インプレッション数、既読数・既読率、タップ推移など、提供された数値のみ。提供されていない指標は「未提供」と書き、推定しない）
  - 訴求内容の分類（例: 実例紹介、Q&A、講座の案内、豆知識など。利用者提供のメモ・キャプションから分類する）
  - 「今週良かった点」「今週の課題」を、実際の数値の比較にもとづいて記述する（数値の裏付けがない主観的な評価はしない）
  - 来週への施策案 3〜5件。各案に「対象読者（A/B）」「意図（集客のどの段階に効くか：認知・関心・講座への誘導など）」「参考にした実績」「注意点」を付ける
  - 集客を目的とするが、成果を誇張する表現・断定的な効果予測はしない
- 人の確認が必要な操作: 投稿・ストーリーズの作成や公開はしない。施策案の実行は利用者が行う
- 実行後に記録すること: `finish` の summary に対象期間、投稿件数、施策案の件数
- 起動方式（素材確認／定期レポート）: periodic（対象期間ベース。inboxに新しいデータが入るたびに実行する運用も可）
- 素材の対象範囲と対応形式: `inbox/weekly-reviewer/` 配下のテキスト・CSV・PDF・docx。数値は利用者提供のものだけを使い、AIが推測で埋めない
- 必要な接続・スキル・ツール: Python 3.10以降。Instagramへのログインはしない（ログイン情報も求めない）
- 同じ素材または同じ期間を再処理しないための基準: 期間キー = 対象週の開始日（日本時間、`YYYY-MM-DD`）。同じ期間キーで再度 `claim` すると `skipped` になる
- 1回あたりの件数・作業量の上限: 1回1レポート、施策案3〜5件
- 情報不足・認証切れ・失敗時の止めどころ: `inbox/weekly-reviewer/` に対象期間のデータがない場合は `fail --status blocked` で理由を記録して終了する。数値が一部しかない場合は、ある範囲だけで作成し、不足箇所を明記する
- 出典・数字・禁止表現などの納品前チェック:
  - 使った数値がすべて `inbox/` 提供資料に基づくか（AIが作った数字が混じっていないか）
  - 「必ず伸びます」「絶対に集客できます」など断定的な効果保証をしていないか
  - 講座の実績・受講者の声を、確認していないのに創作していないか
  - です・ます調か
- フィードバックを反映する場所: 分析の観点や施策の方向性は、このファイルまたは `context/brand-voice.md` に反映。変更履歴は `logs/feedback.md`
